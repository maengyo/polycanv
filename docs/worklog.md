  신뢰되지 않은 훅은 **오류도 경고도 없이 조용히 실행되지 않는다**

### 실측으로 뒤집힌 전제 (6건)

| 처음 판단 | 실측 결과 |
|---|---|
| swap layout 을 2개 두면 토글이 된다 | 기저가 `ExactPanes` 제약이라 순환 주기가 패인 수에 따라 변함 → **캔버스·리스트 둘 다 swap layout 으로** 선언해야 함 |
| codex 는 훅이 없어 패턴매칭이 필요하다 | 훅은 있고 **신뢰 게이트**가 막고 있었다 |
| 파이프가 매달리는 건 원인 불명 | **권한 미승인 인스턴스**에 보내면 unblock 이 거부되어 영구 대기 |
| 권한 부족은 우아하게 실패한다 | **플러그인이 패닉한다.** 값을 반환하는 호출은 `stdin EOF` 로 죽어 오류가 권한을 언급조차 안 함 |
| `hide_floating_panes` 로 플러그인을 숨긴다 | **레이아웃 옵션이 아니다.** 세션 저장용이고, zellij 는 모르는 옵션을 조용히 무시한다 |
| 플러그인 화면은 외부에서 볼 수 없다 | **PTY 를 직접 붙이면 볼 수 있다.** `debug_render` 로 프레임을 로그에 남겨 검증 |

### 만든 것 — 런처 (#3, #14)
- `tools.py` — `~/.config/polycanv/tools.toml`. 첫 실행에 **주석까지 붙여** 만들어 준다.
  빈 파일을 받으면 무엇을 적어야 할지 알 수 없고 대개 문서를 찾으러 가지 않는다.

  감추면 "못 찾는 것"과 "지원 안 하는 것"을 구분할 수 없다.
- 설치 판정은 **이름이 아니라 실행 파일로.** 항목 이름을 바꿔도 판정이 달라지면 안 된다.

### 화면을 찍어 봤더니 — 터미널이 실은 표시 전용이었다

런처가 안 열려서 PTY 캡처를 떴다. `ctrl+n` 이 앱에 닿지 않고 셸에 그대로 찍히고 있었다.
파고들어 보니 문제가 셋이었다.

**1. 키를 전부 안쪽으로 넘기면 앱 단축키가 영영 닿지 않는다.**
그렇다고 `ctrl+n`·`ctrl+w`·`ctrl+t`·`ctrl+q` 를 앱이 가져가면 안 된다 — 전부 readline 이
쓰는 키다. AI CLI 는 특히 `ctrl+c` 로 도는 턴을 끊는 일이 잦다.
→ **접두키 `ctrl+b` 하나만** 가져간다(tmux 와 같은 키). 두 번 누르면 그대로 안으로 보낸다.

**2. `enter` 도 `ctrl+c` 도 PTY 에 전달되지 않고 있었다.**
Textual 의 `event.character` 는 제어키·엔터·화살표에서 전부 `None` 이다(실측).
그 값만 보고 쓰고 있었으니 **명령 하나 실행할 수 없는 상태**였고, 화면에 글자는 찍히니까
눈으로는 멀쩡해 보였다. → `keymap.py` 로 이름을 xterm 시퀀스에 직접 옮긴다.

**3. Textual 이 먼저 채 가는 키가 있다.** `ctrl+q` 는 App 의 priority 바인딩이고
`ctrl+p` 는 명령 팔레트다. 둘 다 되찾아 안으로 돌려보냈다.

**밖으로 나가는 패널도 이때 잡았다.** 끌어서 화면 밖으로 보낼 수 있었는데, 그러면 되찾을
방법이 없다. 자유 배치는 아무 데나 둘 수 있다는 뜻이지 잃어버릴 수 있다는 뜻이 아니다.

### 구동 GIF (README)
`scripts/dev/record-demo.py` — 스크립트대로 조작하고 pyte 로 재생해 GIF 를 뽑는다.
**마우스(SGR)까지 넣어서** 끌어 옮기고 크기 바꾸는 장면을 담았다. 70KB.

  먹지 않는다. 처음엔 앱 버그로 의심했는데 **녹화 도구 쪽 문제였다.**

## 2026-08-20 (3) — 리소스 측정과 최적화

### 요구
외부에서 터미널 여러 개를 띄우는 것과 리소스가 어떻게 다른지 알려주고, 최적화할 것.

### 재는 도구부터 만들었다 — `scripts/dev/bench.py`
혼자 재면 "40MB" 가 큰지 작은지 알 수 없다. 같은 조건으로 셋을 잰다:
셸만(바닥값) · tmux(같은 일을 하는 C 도구) · polycanv.

**벤치마크가 세 번 거짓말했다.** 셋 다 그럴듯한 숫자로 나와서 더 위험했다.
- `ps -o rss= <pid들>` 에서 **`-p` 를 빼먹었다.** 인자가 무시되고 머신 전체가 나온다
  (4개를 물었는데 93개, 셸 4개가 2.6GB로 보였다).
- tmux 를 그냥 띄우면 **사용자가 이미 돌리던 서버에 붙는다.** 남의 세션까지 재서 56MB.
  전용 소켓(`-L`)으로 격리했다.
- 부하 측정에서 **배수 루프가 20ms 씩 잠들었다.** PTY 버퍼가 차서 자식이 쓰기에서 멈추니,
  재는 것이 상대 프로그램이 아니라 이 루프가 됐다 (셸만 재는데 38.61초).
  `select` 로 바꾸니 0.57초.

### 결과 (140x40, RSS 는 프로세스 트리 합계)

| 터미널 수 | 셸만 | tmux | polycanv |
|---|---|---|---|
| 1 | 2.3 MB | 4.8 MB | 54.9 MB |
| 4 | 10.6 MB | 17.0 MB | 60.8 MB |
| 8 | 22.5 MB | 25.3 MB | 74.8 MB |

유휴 CPU 는 셋 다 0.0% 다 (polycanv 는 고치기 전 0.3%).

부하(`seq 1 200000`, 터미널 1개):

| | 걸린 시간 | CPU |
|---|---|---|
| 셸만 (바닥값) | 0.60초 | 0.00초 |
| tmux | 1.14초 | 0.18초 |
| polycanv | 1.84초 | 1.50초 |

**해석**: 메모리는 **고정비**다 — Textual 빈 앱이 이미 28.1MB 다(실측). 터미널당 추가분은
2~3MB 로 작아서, 많이 띄울수록 tmux 와의 격차가 줄어든다. 반면 CPU 는 부하에서 8배다.
파이썬 터미널 에뮬레이터(pyte)를 쓰는 값이고, 렌더링 탓이 아니다 —
**렌더를 통째로 들어내도 1.50 → 1.47초밖에 안 준다.** Textual 이 프레임 단위로 합쳐 준다.

비교로, 이 기계의 Terminal.app 은 **혼자 92MB** 를 쓰고 있었다. 창마다 렌더러가 붙는
GUI 터미널을 여러 개 띄우는 것과 비교하면 polycanv 쪽이 싸다.

### 고친 것

1. **`index()` 가 `pyte.display` 를 불렀다** — 그건 화면 **전체**를 매번 새로 만드는
   속성이다. 줄 하나 밀릴 때마다 부르고 있었다. 한 줄만 만들도록 바꿔 **12배**
   (0.13 → 1.40 MB/s). 내가 스크롤백을 넣으면서 만든 것이다.
2. **성긴 행을 폭 전체로 훑었다** — pyte 의 행은 쓰인 칸만 있는 dict 다. `seq` 처럼 짧은
   줄이 쏟아질 때 140칸을 헛돌았다. 쓰인 데까지만 본다.
3. **패널마다 초당 20번 깨우는 타이머를 없앴다** → `add_reader` 로 읽을 게 있을 때만.
   유휴 CPU 0.3% → 0.0%. 터미널이 늘수록 이득도 는다.
4. 한 번 깨어나면 **있는 만큼 몰아 읽는다.** 다만 한도를 둔다 — 끝없이 뱉는 프로그램이
   있으면 그 함수가 안 돌아와 앱 전체가 멈춘다.
5. 렌더도 `display` 대신 우리 것을 쓴다 (wcwidth·assert 를 줄마다 돌리지 않는다).

**고치지 않은 것**: 재생 버퍼(`_remember`)는 3452 MB/s 였다. 느리지 않은 것을 고칠 이유가 없다.

### 남은 한계
부하 CPU 8배는 pyte 를 쓰는 한 그대로다. AI CLI 를 지켜보는 용도(출력이 뜸하다)에는
문제가 안 되지만, 큰 파일을 `cat` 하는 용도라면 tmux 가 낫다. **그건 정직하게 말해야 한다.**

## 2026-08-20 (4) — 신호등

### 요구
다음 할 일을 정리하고 진행할 것. → 로드맵상 남은 핵심인 **신호등**(#16).

### 옮겨온 것과 새로 만든 것
상태 계약(`status.py`)은 zellij 판에서 **테스트째 옮겼다.** 규칙을 다시 짜지 않은 이유는
그게 이 프로젝트에서 제일 비싸게 얻은 부분이기 때문이다. 전부 한 문장에서 나온다 —
**놓치는 것이 헛보는 것보다 나쁘다**:
- 약한 근거는 주의 상태로 **올릴 수는 있어도 내릴 수는 없다**
- 지나간 이벤트는 버린다
- 들여다본 것은 어떤 이벤트보다 세지만 **🔴 만 푼다.** 🟡 은 쳐다본다고 안 사라진다

훅이 오는 길은 zellij 파이프 대신 **유닉스 소켓**이다. 터미널을 띄울 때
`POLYCANV_SOCKET`·`POLYCANV_PANE` 을 물려주고, `polycanv --hook` 이 stdin 의 JSON 을 읽어
한 줄 보낸다. 그 진입점은 **무슨 일이 있어도 0 으로 끝난다** — 훅이 실패하면 CLI 의 턴이
통째로 멈춘다.

**사용자 설정은 건드리지 않는다.** claude 는 `--settings` 로 덧씌운다(실측). 만든 파일은
임시 디렉터리에 있고 프로세스와 함께 사라진다. 도구 판정은 이름이 아니라 실행 파일로 한다.

### 실측
실제 claude 턴 하나로 끝까지 확인했다:
```
('7', 'idle', 'hook') → ('7', 'running', 'hook') → ('7', 'finished', 'hook')
```
화면에서도 세 상태를 소켓으로 밀어 넣어 색까지 확인했다:
`● afd75f`(초록) / `◆ d7af5f`(호박) / `● ff8787`(빨강).

### 걸린 것
- **유닉스 소켓 경로는 100자쯤에서 잘린다.** pytest 의 `tmp_path` 가 그보다 길어 테스트가
  `AF_UNIX path too long` 으로 터졌다. 제품 쪽에도 한도를 넘으면 짧은 자리로 물러나게 했다.
- **죽은 세션의 소켓 파일이 남는다.** 강제 종료되면 정리가 안 돼서, 다음에 붙으면
  `Connection refused` 가 난다. 실제로 그 함정에 내가 빠졌다. 시작할 때 죽은 PID 의 것만 치운다.
- **신호등에 이모지를 쓰지 않았다.** 두 칸을 먹고 터미널마다 폭이 달라 테두리가 밀린다.
  한 칸 도형에 색을 입혔고, 색이 곧 의미다 — 테마에서 빨강·노랑·초록을 비워 둔 이유가 이것이다.

codex 는 훅 신뢰 게이트(#2), opencode 는 HTTP SSE(#4). 둘 다 이제 붙일 자리는 생겼다.
🔴 깜빡임은 넣지 않았다 — 터미널의 blink 속성은 지원이 들쭉날쭉해서 별도 판단이 필요하다.
