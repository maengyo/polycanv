# 백로그

GitHub 이슈로 등록할 항목. 등록 후에는 이슈가 정본이고 이 파일은 초기 목록으로만 남는다.

각 항목의 근거는 `CLAUDE.md` 와 `docs/research/` 에 있다. **추정과 실측을 구분해 적었다.**

## P0 — 사용자가 처음 켰을 때 막히는 것

### #1 최초 실행 시 권한 승인 안내가 없다
플러그인은 최초 실행 시 zellij 권한 승인을 요구하고, **승인 전에는 로드만 되고 키에 반응하지 않는다.**
사용자에게는 "사이드바가 먹통"으로 보인다. 지금은 `docs/setup.md` 에 적어둔 것이 전부다.
- 필요: 첫 실행 감지 → 안내 표시, 또는 README/설치 스크립트에서 더 강하게 안내
- 근거: 실측. 승인 전 키 입력 무반응 확인

### #2 codex 훅 신뢰 게이트 안내
codex 는 훅을 신뢰시키기 전까지 **오류도 경고도 없이** 상태를 보내지 않는다.
polycanv 는 `--dangerously-bypass-hook-trust` 를 붙이지 않기로 했으므로(사용자 보안 결정),
**신뢰되지 않은 상태를 감지해 안내**해야 한다. 조용히 ⚪ 로 두면 고장으로 오인한다.
- 근거: 실측. 플래그 없이 0건, 붙이면 3건 발화

## P1 — 설계상 알려진 구멍

### #3 런처 도구 목록을 공용 파일로 이전
현재 도구 목록이 **플러그인 인스턴스 설정**에 있다. `zellij pipe` 는 URL+설정으로 인스턴스를
구분하므로, 호출자가 설정 문자열을 토씨까지 맞춰야 한다. 깨지기 쉽다.
- 대안: `config/tools.kdl` 같은 공용 파일에서 읽기
- 근거: 실측. 설정 불일치로 도구가 조용히 실행되지 않는 것을 확인

### #4 opencode 브리지 자동 기동 검증
런처의 **사이드카** 기능으로 브리지를 함께 띄우도록 구현했으나 **실구동은 미검증**이다.
파싱·치환은 단위 테스트로 덮여 있다.
- 필요: 실제 opencode + 브리지로 🟢🟡🔴 흐름 확인

### #5 상태 플러그인이 한 줄을 차지한다
플로팅으로 숨기려 했으나 zellij 레이아웃에 그런 수단이 없어 하단 1행 타일로 두었다.
- 개선안: 그 한 줄에 "N개 실행중 / M개 대기" 요약을 표시해 공간값을 하기

## P2 — 플랫폼 · 배포

### #6 Windows 검증
zellij Windows 네이티브 지원은 2026-03 출시라 예제가 적다. CI 매트릭스에 포함돼 있으나
**실제 동작은 미검증**이다. 특히 패인 제어 API 와 훅 스크립트(셸 차이).

### #7 WSL 검증
`wsl.exe` 를 도구로 띄우는 경로는 pwsh 로 검증된 것과 동일하나, WSL 자체는 미검증.

### #8 GitHub Releases 자동화
현재 CI 는 빌드·테스트만 한다. 태그 푸시 시 wasm 아티팩트를 릴리스에 올리는 워크플로 필요.

## P3 — 미결정 (사양 판단 필요)

### #9 OS 알림 / 사운드
시각 신호등 외에 OS 알림을 보낼지. 여러 세션이 동시에 끝나면 알림 폭탄이 될 수 있다.

### #10 원격 SSH 세션 포함 여부
zellij 는 원격 세션을 다룰 수 있으나, 상태 훅은 원격 CLI 에 심어야 해서 설계가 커진다.

### #11 출력 히스토리 저장 · 검색
"어제 그 세션이 뭐라 했더라"를 푸는 기능. 스크롤백 저장은 용량·프라이버시 문제가 따른다.

### #12 "슈루룩" 전환 애니메이션
현재는 즉시 전환이다. TUI 에서 자연스럽게 표현 가능한지 미검증.
목표 문서에 "미흡하면 즉시 전환 + 시각적 강조로 대체" 로 이미 여지를 두었다.
